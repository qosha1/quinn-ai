# Release v0.3.0

**Release Date:** 2026-04-29
**Release Type:** Minor Release

## Overview

Test-coverage and product-bug-fix release driven by paid live-LLM canary
runs. Ships a 3-tier test stack (e2e smoke, scenario harness, live
canary), several new CLI flags (`--reuse-beads`, `--skip-okrs` actually
working, `--model`, `org okr close`), and a wave of fixes to footguns
the canary surfaced (multi-org tmux session collisions, claude OAuth
conflict, hire/budget ordering, msgr env propagation, default Anthropic
model IDs).

## Highlights

- **3-tier test stack**: e2e (~70 tests, real `qn` + real `bd`), scenario
  harness (YAML-driven, in-process Click + FakeSpawner), live canary
  (paid Anthropic). Real validation across the whole product.
- **Multi-org safety**: `find_orphaned_tmux_sessions` no longer kills
  sibling orgs' worker sessions on a shared machine. Each org's
  cleanup is scoped to its own workers.
- **Hire UX**: `qn org hire` no longer leaves workers stuck at
  `runtime_status='starting'` when the budget allocation isn't there
  yet. Hired workers can use msgr/qn-bd via a 4-tier env-resolution
  fallback (flag → env → cwd → tmux session name).
- **Model pinning works**: `--model <id>` (with `envvar=QUINNAI_CANARY_MODEL`)
  on `qn org start` now actually pins the spawned session's claude
  model instead of inheriting whatever the user is logged into.
- **Board UI**: real modal screens for hire/fire/promote/demote
  (replacing "use the CLI" notification stubs). Org tabs now have
  separate select + close (×) buttons.
- **State-machine validation closed out**: 91 state-machine tests pass
  / 0 xfail (was 75 / 6 / 13 xpassed). STATEMACHINES.md status labels
  refreshed to match the implementation.

## Breaking Changes

- `qn org init` now refuses to share an existing `.beads/` at the target
  path. Pass `--reuse-beads` to opt in to the legacy share-the-tracker
  behavior (only valid when you genuinely own the inherited `.beads/`).
- `working` and `blocked` runtime states removed from `RUNTIME_STATES`.
  No production code wrote them and there was no transition machinery,
  but if anyone was directly writing those values to `worker_state.runtime_status`
  via raw SQL it'll now violate the validation set.
- 4 dead module-shadow facade files deleted (`cli/core/queries.py`, `db.py`,
  `worker.py`, `notifications.py`). All imports already resolve to the
  package equivalents — nothing should be affected — but flagging in
  case external code somehow relied on the module path.

## Migration Guide

For anyone running `qn org init` inside a directory that already has a
`.beads/` (e.g., inside a git repo whose root has its own bead tracker):
the command will now error with a clear message. Options:

1. **Recommended**: init in a clean directory (or `rm -rf .beads/` first
   if the inherited tracker is stale and yours).
2. **Opt-in**: pass `--reuse-beads` to deliberately share the existing
   `.beads/` (your bootstrap OKR + initial tasks will land in that
   tracker).

For test scripts that asserted `qn org start` without
`--skip-config-validation` would fail when no `ANTHROPIC_API_KEY` was
set: that assertion was incorrect. The default `claude_code` provider
uses claude-CLI's auth, not env-var API keys. Tests should either pass
`--skip-config-validation` (when validation isn't the SUT) or assert
against a deliberately-broken provider config.

## New Features

See [CHANGELOG.md](../CHANGELOG.md#030---2026-04-29) for the full list.
Highlights:

- `qn org init --reuse-beads` (opt-in tracker sharing)
- `qn org init --skip-okrs` (actually works now — was suppressing prompt only)
- `qn org start --model <id>` (env-driven via `QUINNAI_CANARY_MODEL`)
- `qn org okr close <id>` (writes to BOTH bead and SQLite mirror)
- `make test-e2e` target + dedicated CI job
- `tests/scenarios/` Tier 2 framework, `tests/canary/` Tier 3 live LLM canary
- Board UI modal screens for team-view actions

## Improvements

- `qn org okr list` is now a single merged view (status from db,
  priority/labels from beads, KRs/progress from db). `--from-db` is a
  deprecated no-op alias kept for back-compat.
- `qn org stop` summary surfaces unacked workers as a clear ⚠ warning
  block on stderr.
- `--org-path` help text unified across all command groups.
- `BRIEFING.md` includes a "How to Break Down Work" section coaching
  the CEO/manager to decompose along (vertical × skillset).
- Default Anthropic model IDs refreshed to current 4.X family
  (Opus 4.7, Sonnet 4.6, Haiku 4.5).

## Bug Fixes

- `find_orphaned_tmux_sessions` killing sibling orgs' sessions on
  shared machines.
- `qn org hire` leaving workers stuck in `starting` state when
  budget allocation was missing.
- Hired workers couldn't use msgr/qn-bd because env didn't propagate
  through claude's Bash tool.
- claude-CLI "Auth conflict" warning when both `ANTHROPIC_API_KEY` and
  OAuth login were present.
- SQLite default datetime adapter deprecation warnings (Python 3.12+).
- `archive.sh duration_seconds=-1` from ISO-8601 timestamp parsing.
- FTS5 wrkr search crash on hyphenated queries.
- `qn config set-provider` rejecting `codex`/`gemini` despite the
  registry shipping them.
- `Org.start()` had no rollback on CEO activation failure (now reverts
  CEO lifecycle status).
- 4 board_ui async tests missing decorators / 1 stale post-merge
  patch target.
- `init_beads` switched from `--non-interactive` (removed in bd 0.43+)
  to `--quiet` (works on both bundled and system bd).

## Dependencies

No new runtime dependencies. The `[board]` extra still exists from 0.2.1
for the Textual TUI dependency.
